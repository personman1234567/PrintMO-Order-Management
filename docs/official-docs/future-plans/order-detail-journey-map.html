Order Detail as a Digital Traveler

Journey + Philosopher exploration, 2026-08-17. This is a candidate experience model, not approved PrintMO workflow policy. It deliberately keeps three operator paths separate because a routine order, a blocked order, and an interrupted handoff do not converge into one honest happy path.

What changed in the framing

  • The order is not primarily a record to inspect; it is a case moving through commitments.
  • Readiness is not a permanent label. It is an evidence-backed claim that can be incomplete, stale, contradicted, or invalidated.
  • The detail experience is a checkpoint: orient, choose the next safe commitment, act, verify the consequence, then exit or hand off.
  • “Alive” means causally responsive—showing what changed and what that unlocks—not decorative animation.
  • Closing, interruption, external-tool work, and return are part of the journey rather than edge cases outside it.

Journey-wide contract

Stable spine across all three arcs
  • Orient: identity, due, source freshness, current commitment, and changes since last view.
  • Decide: one next safe action or one clearly explained reason the system cannot determine it.
  • Resolve: show only the evidence and controls needed for the current workstream, with deeper detail available.
  • Commit: distinguish local draft, pending write, committed state, conflict, and failed write.
  • Consequences: show which milestone changed, which downstream work became possible, and what is next.
  • Exit/handoff: close safely, preserve only intentionally scoped drafts, and leave a recoverable checkpoint.
